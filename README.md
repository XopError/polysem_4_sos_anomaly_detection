Поиск аномальных респондентов в активности поисковых запросов SoS

Команда запуска:
python solution_Борисов_Алексей_Кириллович_ШАД-111.py

Краткое текстовое описание алгоритма:

Аномалией считается чрезмерно высокая дневная активность отдельного респондента по конкретному бренду. Триггером аномалии является набор из идентификатора респондента, даты, идентификатора бренда и категории поставки. Единицей удаления является пара идентификатор респондента и дата. Если респондент признан аномальным хотя бы по одному бренду, из выборки удаляются все его записи за этот день.

Показатель score рассчитывается как доля респондента в общем OTS бренда за день. Сначала вычисляется daily_ots как произведение дневного веса респондента на количество его строк запросов по данному бренду. Затем daily_ots делится на сумму daily_ots всех респондентов по этому бренду за этот день.

Пороги выбираются адаптивно для каждой группы бренд-день-категория. Базовый порог равен максимуму из 99-го процентиля распределения daily_ots в группе и медианы, умноженной на 5. Дополнительно вводится жесткий минимальный порог в 5000, чтобы исключить попадание в аномалии респондентов с малым OTS. Если в группе менее трех респондентов, порог ужесточается до максимума из медианы, умноженной на 10, и минимального порога, чтобы избежать ложных срабатываний на малых выборках.

Выбранный подход разумен, так как он направлен исключительно на поиск экстремально высоких значений, игнорирует малые активности, статистически обоснован через перцентили и медианы, не использует жестко заданные идентификаторы или фиксированные проценты удалений и устойчив к малым выборкам.

Программа работает в несколько этапов. Сначала она загружает данные из папки data_train, фильтрует строки по условию BrandinDelivery равно 1 и валидной категории. Затем агрегирует данные, рассчитывает daily_ots и адаптивные пороги, определяет аномалии и сохраняет их в файлы anomalies.csv и anomaly_reasons.csv. После этого удаляет аномальные записи из исходных данных и строит обязательные графики изменения OTS и количества аномалий. В конце запускается блок аналитических возможностей, который сохраняет дополнительные графики и таблицы в папку additionally.

Пример работы:
Если респондент с весом 5 сделал 3 запроса по бренду, его daily_ots равен 15. Если порог для этого бренда в этот день составил 10, респондент будет помечен как аномальный и удален из выборки за этот день.

Требования перед запуском:
Для корректной работы необходимо, чтобы папка data_train с подпапками month равными дате и файлами parquet находилась в той же директории, что и скрипт. Запускать файл нужно командой python solution_Борисов_Алексей_Кириллович_ШАД-111.py в терминале или командной строке. Предварительно должны быть установлены все библиотеки из файла requirements.txt.
